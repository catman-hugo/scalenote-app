# Version 0.6 plan: offline choices, storage, sharing in and quick capture

Written 2026-11-24 at the owner's request. The spec called 0.6 "Android and offline selection". The owner decided on 2026-11-24 that none of it is Android-only: a laptop goes on the road just like a phone, so offline choices, the storage screen, the share target and quick capture come to **every device** (Windows, Linux and Android).

## The idea in one paragraph

Today every device keeps the whole notes folder. In 0.6 each device can keep **only part of it**. You mark a folder or a page as "available offline" and choose what to keep of it (text, ink and drawings, pictures, PDFs and other files). The rest is still listed, with a cloud icon, and opens when a device that has it can be reached. Next to that, ScaleNote learns to **receive things from other apps** (text, links, pictures, files) and gets a **quick way to start a new page** from outside the app.

## What stays the same

- The notes folder stays plain markdown that Obsidian can open. A file that is not kept on a device is simply not there; nothing in the folder is a stand-in file or a special format.
- There is no central server and there never will be. A device that does not have a page gets it from your own server or another of your own paired devices.
- Nothing received from another app or device is trusted: size limits, nothing executed, paths checked.
- Every write is atomic, and no sync may lose text.

## The rules that make partial sync safe

These are the heart of 0.6. They are decided before any interface is built, and each one gets a test.

1. **"Not kept here" is never "deleted".** A file a device leaves out by choice is never sent as a delete to another device. Today the sync treats a file that disappeared since the last sync as deleted, so the device's keep rules have to be applied to its file list *before* the plan is made, on both sides of every sync.
2. **Freeing space never loses the only copy.** Removing a local copy (by switching an item off, or "Free up space") only removes a file that is identical on at least one paired device, as far as the last sync knows. Anything else is kept and the screen says why ("changed since the last sync", "only on this device").
3. **Changes to items that are not all here are made where they are.** Renaming, moving or deleting a folder (or a page whose drawing is not here) that has files this device does not keep is refused on this device, with a message to do it on a device that has all of them. Otherwise the files elsewhere would stay under the old name. (Built in 0.6.0. Fetching the missing files first and then renaming could come later.)
4. **Keep rules are per device and not synced.** Each device decides for itself what it keeps. The choices live in the hidden `.scalenote/offline.txt` of the notes folder on that device. That file is never synced (from `.scalenote` only the folder colours are), and Obsidian does not show hidden folders.
5. **The whole tree is always known.** Titles, folders and page icons sync for everything, so the page list is the same on every device. A device keeps the list of what exists elsewhere from the last sync.
6. **Attachments follow their pages.** Pictures and PDFs live in the shared `attachments` folder. A file there is kept when at least one kept page links to it *and* that page's choice includes its type. A file no kept page links to follows the setting of the folder it sits in.
7. **Defaults.** On a computer, everything stays offline unless switched off: nothing changes for anyone who never opens the setting. On a phone or tablet, the first sync with a device asks what to keep (see "Open questions").

## How 0.6.0 does it (built 2026-11-24)

- Each device sends its choices with its file list, so the other device knows what not to send and what not to read as deleted. A file a device does not have now, did not have at the last sync, and does not keep, is left out of the sync on both sides.
- "Free up space" writes what it removes to `.scalenote/offline-removed.txt` and takes it out of this device's saved lists. Those files are sent to other devices as "left out" until they are back. The device that started a sync keeps its own saved list, and this is how it learns the file was not deleted.
- Apps before 0.6 read the removed files as left out too, so they never delete them. They do not read the choices, so they can still send a device files it does not keep. **Update every device to 0.6 before choosing what a device keeps.**
- After each sync the device keeps the other device's list (`.scalenote/sync-tree-<device>.txt`). That is what the cloud icons in 0.6.3 come from.

## Sharing with other people (0.6.4)

Asked for on 2026-11-25: share a page or folder with another person's **account**, not one device, so they have it on all their devices, and work on it together: live when both are nearby, or offline, with changes joined afterwards.

Decided by the owner (2026-11-25):
- **A shared page lands in "Shared with me/<name>/"** in the other person's notes (for example `Shared with me/Rowan/Biology`). They can move it from there.
- **The other person accepts first.** Their device shows "Rowan wants to share Biology with you" with Accept and No. Nothing arrives unasked.

How it works (proposal, to be confirmed while building):
- **An account is a person:** a user name (chosen once) and the devices paired with each other, as today. Paired devices share the account's name and its shares, so a share given to a person reaches all of their devices.
- **Choosing who to share with:** right-click a page or folder, **Share…**, and pick a user name from the people whose devices are on the same network right now (home Wi-Fi, a hotspot, a cable). Later a person can be kept in a list, so a share goes on when they are seen again.
- **Same connection as sync:** the same encrypted direct connection, no server; only the shared page or folder is ever sent to the other person, never the rest of the notes.
- **More often:** a shared page that is open on both sides is synced every few seconds and right after each pause in typing; otherwise with the normal 30-second checks.
- **Joining edits automatically (new):** today a page changed on two devices is kept twice and the person picks one (Review conflict copies). For sharing, changes are joined automatically against the version both had last, word by word; only when both changed the same words are both kept, as today. This also applies to sync between one's own devices.
- **Rights:** the owner can stop sharing; the other person can leave. Removing a share never deletes anyone's copy: it stops syncing.

## Things that are not in 0.6

- Sync while the app is closed on Android (still a later improvement, as in 0.5).
- The browser client (later release, no number yet).
- The Windows system share menu ("Share" in Windows' own share window). It only works for apps installed as an MSIX package; ScaleNote installs from an `.msi` and updates itself with signed updates. "Send to" and "Open with" cover the same need. Can be looked at again if the installer ever changes.
- Making ScaleNote the default app for `.md` files: it is on the feature list as its own setting (`docs/features-to-implement.md`). 0.6 only adds ScaleNote to the "Open with" list.

## Before January 2027: Android developer registration

From January 2027 Android only installs apps from registered developers without extra steps. Anyone else has to switch on Android's "advanced flow" once per device (developer options, a restart and a 24-hour wait), or install with ADB. Options for ScaleNote:

- A free **limited distribution** account: up to 20 devices, each one added by the person on that device, no ID needed.
- A **full distribution** account: a one-time $25 fee and an ID check, unlimited installs, still without Google Play (GitHub and F-Droid keep working). This is the one a public release (2.0.0) needs.
- Neither: every tester uses the advanced flow once.

An account type cannot be changed later; moving from limited to full means a new account and moving the package name over. **The owner decides**; if an account is used, the package name has to be registered before January.
