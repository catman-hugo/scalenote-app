The v1 spec describes 0.4 as "Blocks, Split and Canvas modes, pressure-sensitive drawing tools, lasso, anchored draw-over-text, PDF import". That is too much for one build, so it is built in slices, like 0.3. Each slice is one version number, one branch and one pull request. The order is the owner's to change.

Choices made at the start (the owner chose "Canvas page: pen + eraser" as the first slice, 2026-11-06):
- The first slice is the drawing sheet itself, with no connection to the text of the page, because everything later (anchoring, split view, PDF) needs the sheet, the pen and the storage to work first.
- Draw over text is the hardest part and gets its own slice, so that it can be tried on a device before anything is built on it.

## Canvas and pen (0.4.0)
- A page has a "Canvas" button next to "Markdown" at the top. It switches the page to its drawing sheet and back. Opening another page leaves the canvas. The text of the page is not touched by anything drawn.
- The drawing is stored in `Name.canvas.json` next to `Name.md`, one stroke per line. Obsidian ignores it. It follows the page when the page is renamed, moved, deleted to the trash or restored. See DECISIONS.md.
- Tools: pen, eraser (removes whole strokes), move the sheet. Six pen colours (the theme's text colour and the five accent colours the text colours use, so they change with the theme) and three widths. Pressure from the pen makes the line thinner or thicker; a mouse draws the plain width.
- A pen or a mouse draws. A finger moves the sheet (one finger) or zooms it (two fingers); "Finger draws" turns that around for a device with no pen. The barrel button or the eraser end of a pen erases while held. The mouse wheel moves the sheet, Ctrl and the wheel (or a trackpad pinch) zooms, space with a mouse moves the sheet. Undo and Redo by button, Ctrl+Z and Ctrl+Shift+Z.
- Limits: 20,000 strokes, 5,000 points per stroke, 1,000,000 points in all, a 32 MiB file. At the limit the drawing says it is full and does not add more.
- A drawing that cannot be read (damaged, or from a newer version) is shown as far as possible and never changed or saved over. If the file is changed by another program while the canvas is open, saving stops and the other drawing is kept.
- Not in 0.4.0: highlighter, shapes, sticky notes, lasso, drawing over text, split mode, PDF import, exporting or printing a drawing, a drawing in the page history, erasing part of a stroke, an infinite sheet scrollbar or minimap.

## Highlighter, shapes, sticky notes, lasso (0.4.1)
- New tools next to the pen: select with a loop, highlighter, line, arrow, rectangle, ellipse, sticky note. They share the colour and width choice. A highlighter line is four times as wide as the pen line of the same width, see-through, and ignores pressure.
- A loop selects what it surrounds (items with at least half of their points inside). Drag the selection to move it; Delete, the trash button or Escape. Undo and Redo cover moves, deletes and note text.
- A sticky note is a coloured box with text, typed in a text box over the sheet. A note with no text is not added.
- The side button of a pen is a setting (Settings, "Drawing"): erase, select with a loop, or nothing.
- File format 2 holds all of this; a pen-only drawing stays format 1. See DECISIONS.md.
- Not in 0.4.1: resizing, recolouring a selection, copy and paste, free text, connectors.

## Draw over text (0.4.10)
Owner request: draw on the text of a page, with the pen menu of ScaleNote v1 for the colours.
- Pen menu. v1 had a toolbar with presets (black, white, red, green), a custom colour and thickness buttons. ScaleNote already has the sixteen OneNote colours and five widths from the canvas (0.4.4), which are a superset of that, so the same colour menu and width slider are reused. The custom "#" colour of v1 is not added: a colour that is not one of the sixteen would need a new file format and does not follow the theme.
- Placement. The pen bar is a row above the text, the same row style as the canvas toolbar, and only there while drawing. It does not float over the text, so it never covers the first lines. A pen button on the top bar (next to History) starts and stops drawing (the bar had a Done button in 0.4.10; it was removed in 0.4.11, the pen button is the only switch). The command palette has "Draw on the text of this page".
- Why not like v1. v1 laid one transparent canvas over the whole editor, not tied to the text, so ink drifts off the words when the text changes. Here every stroke is tied to the block of the text it starts in.
- Anchoring. The sheet is only as big as the visible part of the text box and is redrawn on scroll. A stroke belongs to the block (a child of the editor root) under its first point. Its points are fractions of that block's width and height. The block is found again by its place and a fingerprint (kind and the first 40 characters of its text); if the place no longer matches, the nearest block with the same fingerprint is used; if none matches the stroke is kept in the file but not drawn.
- Storage. Format 5 of `Name.canvas.json`: a separate `ink` list next to `items` (so the canvas view, its selection, erasing and zoom never see ink). Written only when ink exists, so a drawing without ink stays readable by older versions. Same limits as strokes. Pure rules in `web/textink.js`, panel in `web/inklayer.js`.
- Input. A pen or a mouse draws; a finger scrolls the page unless "Finger draws" is on; the pen's eraser end erases. Undo and Redo use the same history class as the canvas.
- Not in this slice: ink in print and export, moving or selecting ink, shapes and notes over text, ink inside a single column (ink in columns anchors to the whole columns block), re-anchoring after large edits beyond the fingerprint rule.

## The `/canvas` block (0.4.11, planned)
Added at the owner's request (2026-11-06), after he asked whether something like `/canvas` from ScaleNote v1 was planned. The v1 spec's slash menu has "Canvas (embeds a region of the page's canvas)".
- Typing `/canvas` in the text of a page puts a block in the text that shows one region of that page's canvas, at a fixed size in the text. Drawing in the block draws on the page's canvas, inside that region, with the same tools as the Canvas mode. Opening the whole canvas shows the same drawing, so the block is a window onto it, not a separate drawing.
- It comes after drawing over text (0.4.10) because it needs the same link between the text of a page and its drawing (blocks that know about the drawing). It also needs the tools of 0.4.1.
- How ScaleNote v1 does it (read 2026-11-11): `CanvasEmbed.ts` is an atom block holding only a `regionId`. That id points to a "frame" object on the one shared canvas (a rectangle with a label, created at the same moment by the slash command). `CanvasEmbedView.tsx` draws a read-only snapshot of the canvas through that frame (the viewport moved to the frame's corner, sticky notes drawn as page elements on top) at the frame's fixed pixel size, under a small title strip. If the frame is gone it shows "Canvas region not found". Nothing can be drawn in the block; the comment in the code says it does not even filter by frame yet. So v1 gives a window, not a drawing surface.
- How it could work in ScaleNote. The page's canvas stays the single drawing. A region is a new kind of item on the sheet: a frame with an id, a position, a size and a label (a new file format, 6, only written when a frame exists, like clips in format 4). The block in the text holds the frame's id. The block shows the frame's part of the sheet using the existing painting code with the view moved to the frame (the same painting as the canvas, so highlights, shapes, notes and paper all appear). Unlike v1 the block can be drawn in: pen and mouse draw as on the canvas, with the coordinates converted to the sheet, and the loop, eraser and undo are the canvas's own. A region can be moved and resized on the full canvas (it is a figure there, like a rectangle) and resized in the text by its bottom edge.
- Markdown storage options (owner to choose before building): (A) an html comment line, for example `<!-- scalenote:canvas id=abc123 -->`: invisible in Obsidian and every other reader, and unknown syntax is kept byte for byte, but a reader sees nothing and a human editing the file cannot see it; (B) a fenced block, for example three backticks `scalenote-canvas` with `id: abc123` inside: Obsidian shows it as a small code block, clearly marking that something lives here, and it is plain markdown; (C) an image-style embed of the drawing file with a region, `![[Name.canvas.json#abc123]]`: Obsidian would try to open a file type it does not know and show a broken embed. Recommendation: (B) for being honest and harmless, with (A) as the quieter choice if he does not want to see it in Obsidian at all.
- What it does not copy from v1: the block is not read-only, and it does not depend on the canvas being open or on a shared document.
- DECIDED (2026-11-12, owner delegated the choice): option B, a fenced block `scalenote-canvas` with `id:`. The text below this line was written before that.
- How the block is stored in the markdown is not decided yet. It must keep the clean-markdown rule (Obsidian shows it as something harmless, and unknown syntax is kept byte for byte). Decide at the start of 0.4.11, with the owner, before building.
- Questions to settle then: can a region be moved or resized; can there be several blocks on one page (each its own region of the same canvas); what happens to the drawing inside a region when the block is deleted (keep it on the canvas, the safe default).
- Not planned for this slice: a canvas block that holds its own separate drawing, and blocks that show another page's canvas.

## Compact toolbar and sidebar buttons (0.4.2)
Owner request (2026-11-06), after trying 0.4.1 on the tablet: the drawing area was too thin because the toolbar took three lines, drop-downs or toggles in the toolbar would help, and Settings, Tags and Trash should look and behave like New page and New folder.
- The toolbar keeps the main tools in view (select, pen, highlighter, eraser, move, note, undo, redo, delete selection). Shapes, colour, line width and the less used switches (Finger draws, Show all) are menus that open under their button. A menu button shows what is chosen now: the shape used last, the colour, the line width. A menu closes when something is chosen, on Escape, on a press anywhere else, or on pressing its button again (Finger draws is a switch, so its menu stays open to show it).
- The toolbar is one line on a wide window and two on a phone, where it used to be three.
- Settings, Tags and Trash are outlined buttons with an icon and a label on one line, like New page and New folder, and the label goes away (leaving the icon, with the label as its name) when the list is narrower than 17 rem.
